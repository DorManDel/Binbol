# Binbol · Reproducible example comparison (2026-11-18)

**Workload:** UTF-8 bytes of `player.health -= damage;\n` repeated eight times. There are 25 bytes per line, 200 bytes total. The newline is included. This is an intentionally favorable case for dictionaries and conventional compressors; do not generalize from it.

| Representation | Total stored / sent bytes | Change vs raw | Accounting |
| --- | ---: | ---: | --- |
| Raw UTF-8 | **200** | 0% | 8 × 25 |
| Binbol BNB1, pre-shared dictionary | **23** | 88.5% smaller | 7-byte header + eight 2-byte token references. Dictionary distribution **excluded** |
| Binbol BNB1, embedded dictionary | **52** | 74.0% smaller | 7-byte header + 29-byte dictionary + eight 2-byte token references |
| gzip, Node.js built-in default | **48** | 76.0% smaller | Complete gzip stream |
| Brotli, Node.js built-in default | **33** | 83.5% smaller | Complete Brotli stream |
| Zstandard, CLI `zstd -3 --stdout -q` | **45** | 77.5% smaller | Complete Zstandard frame |

*Locally rerun with `node scripts/bench_example.cjs`; Zstandard result appears when `zstd` is installed.* Compression library versions and platform can change timings and sometimes byte counts. The figures above are **size comparisons, not speed benchmarks**.

**Interpretation:** pre-shared Binbol is the smallest in this one example, but this result assumes the recipient already knows the dictionary. Brotli is smaller than the self-contained Binbol file. The results do not show that Binbol is better in general or that it provides encryption.
