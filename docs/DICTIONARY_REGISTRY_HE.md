# Binbol — Dictionary Registry v1

## הרעיון בשפה פשוטה

מילון של מילונים: לכל מילון יש נושא (Code, Testing, Messages). לכל ערך יש מזהה בינארי, שם, סמל ותוכן. ערך מסוג Recipe מפנה לערכים אחרים, כמו מתכון שמורכב ממתכונים קטנים.

**מה אנחנו רוצים להוכיח?** שאפשר לקודד טקסט או תוכנית קטנה למזהים קצרים, לשמור את המשמעות, להציג סמלים שניתן לפתוח, ולשחזר את המקור בלי לאבד תווים.

## סדר הניסוי

| שלב | מה עושים | למה | איך בודקים |
| --- | --- | --- | --- |
| 1 | בוחרים מילון | קובעים את המשמעות של המזהים | משווים IDs של Code, Testing ו-Messages |

## דוגמת CHECK_PLAYER

code:1 → LOAD player.health

code:2 → COMPARE 0

code:3 → JUMP_IF_LE gameOver

code:4 → PRINT Player alive

code:5 → Recipe שמפנה לארבעת המזהים שלמעלה

הסמל של CHECK_PLAYER יכול לקבל את המזהה הלוגי 0x0105. ההפניה עצמה קצרה, אבל **ההגדרות במילון לא נוצרות בחינם**. הקוד הוא דוגמה סמנטית ולא תוכנית C שמורצת על מעבד.

## שני מצבי העברה

**Shared:** שני מחשבים מכירים מראש את אותו המילון, ולכן החבילה לא צריכה לצרף אותו. צריך לספור את עלות ההפצה הראשונית אם משווים עלות כוללת.

**Embedded:** המילון מצורף לחבילה, ואפשר לפענח אותה גם ללא התקנה מראש. עלות ההודעה גדלה בהתאם.

הפייפליין: Source → Registry lookup → Binary packet → Transfer → Registry validation → Decode → Original text / Tiles.

## מה פתרנו, ומה לא?

- הפניות מעגליות נדחות: הבדיקה משתמשת בגרף DAG ו-DFS, ומגבילה עומק וגודל פתיחה.
- חבילה לא תואמת נדחית בעזרת גרסה ו-FNV-1a fingerprint. זו בדיקת התאמה, **לא אימות קריפטוגרפי**.
- מילון לא מוכר אינו הצפנה. הגנת הודעות אמיתית דורשת מנגנוני הצפנה מאומתת וניהול מפתחות.
- לא הוכחנו יתרון ביצועים. נמדוד בהמשך צריכת RAM, זמן קידוד ופענוח, ותוצאות מול דחיסה רגילה.
- אין במעבדה חיבור רשת אמיתי, הרצת קוד C שרירותי או קוונטיזציה של מדיה.

## הצעד הבא

Adaptive Dictionary Profiler: להגדיר כמה פרופילים, למדוד אותם על נתונים מגוונים, ולבחור לפי Storage, Speed, Reliability ו-Readability. לקריאה נוספת ראו את מסמך המקורות של הפרויקט.
